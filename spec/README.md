# Spec

The shared contract between upstream [erdify](https://github.com/devsuit-berlin/erdify)
(Python) and the ports in this repository. A port is correct when it passes
every fixture here byte for byte.

| Path | What it defines |
|---|---|
| [`ir.schema.json`](ir.schema.json) | The neutral model that parsers produce and renderers consume. It is the same as upstream's `--format json` output. |
| [`cli.md`](cli.md) | Options, which setting wins, output naming, exit codes, error messages, `--inject` rules, known upstream quirks. |
| [`fixtures/<case>/`](fixtures) | Render fixtures (see below). |
| [`inject/cases.json`](inject/cases.json) | `--inject` cases: Markdown in, Markdown or error message out. |
| [`VERSION`](VERSION) | Spec version and the upstream erdify version it was generated from. |

**Do not edit anything under `fixtures/` or `inject/` by hand.** It is all
generated by [`oracle/build_fixtures.py`](../oracle/build_fixtures.py), which
runs the real erdify. CI fails if the committed files are out of date.

## Render fixtures

Each `fixtures/<case>/` holds:

- `case.json`: where the models came from in upstream's repository, the parse
  options and title used, and which option variants exist.
- `model.json`: the parsed model. This is the **input** for a port's renderer
  tests, and also the expected output for `--format json`.
- `<variant>.puml`, `.mmd`, `.html` (and `.json` for non-default variants): the
  expected output for each format. Variants are `default`, `no-enums` and
  `no-relationships`. Their render options are listed in `case.json`.

A port's conformance test, in any language:

```
for each case:
    model = load(case/model.json)
    for each variant, format in case:
        assert render(format, model, variant options) == read_bytes(case/<variant>.<ext>)
    assert to_json(model) == read_bytes(case/model.json)
```

Files have **no trailing newline** and use `\n` line endings, because erdify
writes them that way. Compare bytes, not trimmed strings.

These fixtures test the **renderers**. Each port also needs parser fixtures in
its own language (Laravel migrations, JPA entities), with golden files named
`expected.json` / `expected.puml` / `expected.mmd`.
`oracle/crosscheck.py` renders each port's `expected.json` with the real
erdify and checks the port's rendered files match.

The `example_*` cases are the reference for the parsers: the Eloquent and JPA
versions of the same `User`/`Order` schema must render
`example_sqlmodel/default.mmd` with the same entities, keys and relationships.
Only the column types differ, because each language has its own (`bigint`,
`Long` and `int` for the same column).

## Updating to a new upstream release

1. Bump `erdify[sql]==X.Y.Z` in `oracle/pyproject.toml`, `UPSTREAM_TAG` in
   `oracle/build_fixtures.py` and the upstream line in `VERSION`.
2. `cd oracle && uv run build_fixtures.py`
3. Review the diff. A changed fixture is a behaviour change that the ports must
   follow. Bump the spec version.
